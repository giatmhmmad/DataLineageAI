## Ringkasan Project

Aplikasi Django untuk manajemen data lineage ETL (Bank Mandiri, Tim Data Management ODP-IT), dengan AI Chatbot berbasis Groq API dan integrasi n8n untuk otomasi deteksi upload job. Git repo berada di `data-lineage/` (bukan di root folder `V2`), berisi 81 file ter-track, ~20 commit, masih tahap pengembangan aktif.

## Fakta Arsitektur yang Sudah Terverifikasi

- Django monolith, satu app (`main`), tidak ada pemisahan app per domain.
- Dual-database: `default` (dikelola penuh via Django ORM/migrations) dan `bot_eda` (3 model `managed=False`, dimiliki n8n, diakses via `BotEdaRouter`).
- n8n terhubung dua arah: webhook masuk (`/api/n8n/lineage/`) dan akses langsung ke DB `bot_eda` (Postgres node + `postgresTrigger`). Workflow n8n memakai `@n8n/n8n-nodes-langchain.agent` + `lmChatGroq` untuk deteksi schema/kategori tabel.
- Chatbot: intent-detection rule-based (keyword Bahasa Indonesia) → query data manual → HTML tabel dibangun di Python → Groq hanya untuk narasi.
- Deployment: Railway (nixpacks, Gunicorn 3 workers) + Neon Postgres. Riwayat commit menunjukkan sempat dicoba di Render dan Koyeb sebelum settle di Railway.
- Tidak ada CI/CD pipeline (tidak ditemukan `.github/workflows` atau setara).
- `.env` dan `*.dump`/`*.sql` sudah benar di-`.gitignore`; **`settings.py` dengan kredensial hardcoded tetap ter-track**.

## Area yang Bekerja Baik (Jangan Diubah Tanpa Alasan Kuat)

- `api_get_lineage` (BFS traversal iteratif, adjacency map in-memory, depth-limit) — desain performa yang sudah baik.
- Pemisahan tanggung jawab LLM (narasi) vs data (Python) di chatbot — mengurangi risiko halusinasi angka.
- `BotEdaRouter` — implementasi router database yang bersih dan idiomatik.
- Konfigurasi production (Railway/Neon) sudah terpisah rapi dari fallback lokal via pengecekan env var.
- `.gitignore` sudah benar mengecualikan `.env` dan file dump database.

## Keputusan / Area yang Sengaja Tidak Diubah Dulu

- **Refactor `main` app menjadi multiple Django apps** — nilai jangka panjang jelas, tapi ditunda karena project masih iterasi cepat; risiko merge conflict lebih besar dari manfaat saat ini.
- **Caching/read-replica untuk performa** — dataset masih relatif kecil (2969 relasi saat audit); optimasi ini prematur tanpa bukti profiling nyata.
- **Mengganti intent-detection rule-based dengan pure-LLM function-calling** — trade-off reliability vs fleksibilitas, butuh keputusan produk eksplisit, bukan keputusan teknis sepihak.
- **Mengubah `bot_eda` unmanaged models jadi `managed=True`** — akan memutus kontrak dengan n8n yang saat ini memiliki skema tersebut; butuh koordinasi lintas sistem.
